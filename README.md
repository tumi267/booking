# middleware.ts Documentation

## Overview

This file configures global application middleware using Clerk authentication and Next.js middleware support.

The middleware runs at the Edge before requests reach application routes.

Primary responsibilities:

- Protect authenticated routes
- Redirect unauthenticated users
- Attach authentication logic globally
- Prevent unauthorized access at the server edge

---

# File Location

Typical location:

```txt
/middleware.ts
```

This file must exist at the project root for Next.js middleware to function correctly.

---

# Middleware Logic

```ts
export default clerkMiddleware(async (auth, req) => {
```

## Purpose

Wraps middleware execution with Clerk authentication context.

The middleware executes on every matched request.

---

# Authentication Retrieval

```ts
const { userId, redirectToSignIn } = await auth();
```

## Purpose

Retrieves authentication state for the incoming request.

## Values

| Variable | Purpose |
|---|---|
| `userId` | Current authenticated user ID |
| `redirectToSignIn` | Clerk helper for auth redirects |

---

# Unauthorized Access Protection

```ts
if (protectedRoutes(req) && !userId)
```

## Logic

Checks:

1. Is the route protected?
2. Is the user unauthenticated?

If both conditions are true:

- User is redirected to sign-in page.

---

# Redirect Logic

```ts
const signInUrl = new URL('/singin', req.url)
```

## Purpose

Creates redirect URL for authentication.

---

# Redirect Preservation

```ts
signInUrl.searchParams.set('redirectTo', req.nextUrl.pathname)
```

## Purpose

Stores original requested path.

Example:

```txt
User tries:
  /booking/checkout

Redirect becomes:
  /signin?redirectTo=/booking/checkout
```

After successful login, the app can redirect the user back.

---

# Edge Redirect Response

```ts
return NextResponse.redirect(signInUrl)
```

## Purpose

Stops request execution and redirects immediately.

## Security Benefit

Unauthorized users never reach:

- Page rendering
- Server actions
- Database queries
- Protected API logic

---

# Successful Request Flow

```ts
return NextResponse.next();
```

## Purpose

Allows authenticated or public requests to continue normally.

---

# Middleware Matcher Configuration

```ts
export const config = {
  matcher: [
    '/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jpe?g|webp|png|gif|svg|ttf|woff2?|ico|csv|docx?|xlsx?|zip|webmanifest)).*)',
    '/(api|trpc)(.*)',
  ],
};
```

---

# Matcher Purpose

Controls which requests execute middleware.

This prevents middleware from running unnecessarily on:

- Static assets
- Images
- CSS
- JavaScript bundles
- Fonts

---

# Excluded Paths

The matcher skips:

```txt
/_next
/*.css
/*.js
/*.png
/*.jpg
/*.svg
```

This improves performance significantly.

---

# API Protection

```ts
'/(api|trpc)(.*)'
```

## Purpose

Ensures middleware also runs for:

- API routes
- tRPC endpoints

This allows authentication enforcement across backend APIs.

# Important Notes

## Sign-In Route Typo

Current code:

```ts
'/singin'
```

Potential issue:

Likely intended:

```ts
'/signin'
```

If the actual route is `/signin`, this typo will cause broken redirects.

---

# Suggested Improvement

Instead of manually building URLs:

```ts
const signInUrl = new URL('/signin', req.url)
```

Clerk helper could also be used:

```ts
return redirectToSignIn()
```

However, the current implementation is useful because it preserves:

```txt
redirectTo
```

state manually.
